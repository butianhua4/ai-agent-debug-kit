# Client Intake Form - AI Automation Emergency Rescue

Use this form before accepting or quoting rescue work.

Do not ask for passwords, API keys, OAuth tokens, cookies, payment information,
wallet details, KYC material, tax documents, private customer records, or
off-platform payment.

## Required Intake

1. Tool or platform name

   Example: n8n, Make, Zapier, Pipedream, OpenAI API, custom Node.js, GitHub
   Actions, LangChain, browser automation, internal script.

2. Error screenshot

   Upload or paste a screenshot with secrets hidden.

3. Sanitized log

   Paste only the relevant redacted log lines. Remove API keys, tokens, emails,
   phone numbers, customer names, and private IDs where possible.

4. Expected result

   What should the workflow do when it works?

5. Actual result

   What happens now?

6. Last known good run

   When did it last work correctly?

7. Business impact

   What is affected: leads, orders, support, content, reporting, internal
   operations, release, or another workflow?

8. Deadline

   When do you need the diagnosis or rescue plan?

## Optional But Helpful

- What changed recently?
- Which step fails?
- Is this a production workflow?
- How often does it fail?
- Can you share a public repo link or redacted workflow export?
- What output do you want: diagnosis only, fix plan, small snippet, CI check, or
  handoff report?

## Safety Reminder To Client

Please do not send passwords, API keys, OAuth tokens, session cookies, payment
data, wallet details, KYC documents, tax information, or private customer data.
Sanitized logs and screenshots are enough for the first diagnosis.
