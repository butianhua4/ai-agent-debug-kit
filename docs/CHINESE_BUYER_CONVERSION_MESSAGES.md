# 中文买家转化短消息

用于买家对自动化故障诊断感兴趣后，把对话推进到“看样例 -> 填需求表 -> 报价”的路径。

核心原则：

- 不要一上来要账号。
- 不要收密码、API Key、Token、Cookie。
- 不要碰支付、KYC、钱包、身份、税务、私密客户数据。
- 不承诺保证修好，只承诺固定范围诊断和可执行报告。

## 样例报告 + 需求表

可以，我这边是先做脱敏诊断，不碰账号、不需要密码或 API Key。  

你可以先看一下 299 元入门诊断的样例报告，交付内容大概就是：故障现象、失败节点地图、可能原因、修复顺序和安全测试清单。  

样例报告：`docs/examples/chinese-299-diagnosis-sample-report.md`  
需求表：`docs/CHINESE_BUYER_INTAKE_FORM.md`

你按需求表发我信息就行，我先判断适不适合 299 入门诊断；如果是完整流程问题，再建议 999 或 1999+。

## 只发一段的极短版

可以，我先不碰账号，也不要密码/API Key。你按这个结构发我：平台、失败步骤、完整错误、最近改动、期望输出、实际输出。  
我会先判断能不能做 299 入门诊断；交付是故障原因、失败节点、修复顺序和测试清单。

## 买家问“能不能直接修”

可以分两步走更稳：  

第一步先做脱敏诊断，确认失败点和修复顺序，不碰账号。  
第二步如果确实需要登录平台实施修复，再重新确认权限、范围和安全边界。  

这样能避免一上来改坏生产流程，也避免泄露密码/API Key。

## 买家问“为什么要先诊断”

因为自动化故障常见原因很多：字段变了、鉴权过期、webhook payload 结构变了、重试循环、下游 API 改规则、AI 输出格式不稳定。  

先诊断能快速判断是一个字段问题，还是完整流程问题。小问题走 299，不会把你推到大单；完整流程再走 999 或加急。

## 买家问“299 交付什么”

299 入门诊断交付一页报告：

- 当前故障现象
- 最可能原因
- 失败节点地图
- 建议修复顺序
- 安全测试清单
- 是否建议升级到完整救援

默认不需要账号密码，只看脱敏错误文本、截图或测试样例。

## 买家问“多久”

如果信息完整，299 入门诊断通常可以当天给出。  
如果缺少错误文本或失败步骤，需要先补信息；我不会在信息不足时硬报价。

## 买家发敏感信息前提醒

先提醒一下：请不要发密码、API Key、Token、Cookie、付款信息、身份证、钱包私钥、未脱敏客户数据。  

如果你要发截图或 workflow 导出，请先把这些内容遮住或删除。我只需要失败步骤、错误文本、输入样例和期望输出。

## 信息不足时

现在还不能判断价格，因为缺少：

- 失败步骤
- 完整错误文本
- 期望输出 / 实际输出

你先补这三项，我再判断是 299 入门诊断，还是需要 999 标准救援报告。

## 可接单确认

这个需求可以接，建议先做 299 入门诊断。  

交付内容是一页诊断报告：可能原因、失败节点、修复顺序和测试清单。  

确认前请再检查一下你发的材料里没有密码、API Key、Token、客户隐私或支付/KYC/钱包信息。

## 升级到 999

这个不是单个字段问题，已经涉及完整流程：触发、字段映射、下游写入和重复发送风险。  

建议走 999 标准救援报告，交付会比 299 更完整：流程失败地图、根因分析、字段修复建议、重复发送风险、Before/After 测试清单。

## 升级到 1999+

如果这个流程正在影响线索、CRM、内容生产、客户通知或业务收入，建议走 1999+ 加急业务救援。  

交付会包括优先诊断、风险地图、修复顺序、备用路径、监控清单和团队交接报告。

## 安全拒绝

这个需求我不能接，因为涉及账号敏感权限、支付/KYC/钱包/身份/税务或未脱敏客户数据。  

你可以先找平台官方支持或内部有权限的人处理。我这边可以继续帮你做脱敏后的错误文本、失败步骤和流程逻辑诊断。
