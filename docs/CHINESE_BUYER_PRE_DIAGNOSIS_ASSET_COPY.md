# Chinese Buyer Pre-Diagnosis Asset Copy

Use this copy pack to create a buyer-facing image, PDF, pinned comment, or first-message card explaining what a buyer should send before a RMB 299 AI automation diagnosis.

The goal is to reduce low-quality chats, prevent unsafe credential sharing, and make qualified buyers faster to route into paid diagnosis.

## Image Card 1 - What To Send

Title:

下单前请准备这 5 样材料

Body:

做 AI 自动化故障诊断前，请先准备：

1. 你用的平台  
   n8n / Make / Zapier / Dify / Coze / Webhook / API / 自写脚本

2. 哪一步失败  
   截图里能看到失败节点即可

3. 报错文字  
   能复制就直接复制

4. 一条脱敏输入样例  
   隐藏姓名、手机号、邮箱、订单号、Token、Cookie

5. 你希望输出什么结果  
   例如：写入表格、发送消息、同步 CRM、生成 JSON

Footer:

材料越清楚，299 诊断越快。

## Image Card 2 - What Not To Send

Title:

这些信息不要发

Body:

为了保护你的账号和数据，请不要发送：

- 账号密码
- API Key / Token / Cookie
- 客户名单
- 私人仓库权限
- 付款、钱包、KYC、税务资料
- 生产后台管理员权限
- 外部确认链接

Footer:

我只基于脱敏截图、报错和样例输入输出做诊断。

## Image Card 3 - What 299 Includes

Title:

299 诊断报告会写什么？

Body:

你会拿到一份中文诊断报告，包含：

- 当前目标
- 失败节点
- 报错证据
- 最可能原因
- 最小测试步骤
- 风险提醒
- 下一步建议
- 是否适合升级 999 修复方案

Footer:

299 是诊断报告，不是直接登录后台修系统。

## Image Card 4 - Package Decision

Title:

299 / 999 / 1999+ 怎么选？

Body:

299：先判断问题卡在哪里  
适合单点报错、字段映射、Webhook、JSON、AI 输出格式问题。

999：诊断后写修复方案  
适合一个清晰的小范围修复路径。

1999+：复杂救援重新拆范围  
适合多流程、生产风险、重复发送、成本异常、长期不稳定。

Footer:

先诊断，再决定要不要修。

## PDF One-Page Copy

### AI 自动化故障诊断材料说明

适合：

- n8n / Make / Zapier / Dify / Coze / Webhook / API / JSON 报错；
- 字段映射错；
- AI Agent 输出格式不稳定；
- 重复发送；
- 自动化成本异常；
- 自己用 AI 搭流程但不知道哪里错。

请提供：

1. 平台名称；
2. 失败节点截图；
3. 报错文字；
4. 一条脱敏输入样例；
5. 期望输出。

请不要提供：

- 账号密码；
- API Key / Token / Cookie；
- 客户名单；
- 私人仓库权限；
- 付款、钱包、KYC、税务资料；
- 生产后台管理员权限。

交付：

299 元中文诊断报告，包含失败点、证据、可能原因、最小测试步骤、风险提醒和下一步建议。

边界：

299 是诊断，不保证直接修好整套系统；如需修复方案，诊断后再判断是否适合 999 或 1999+。

## Safety Check

Before publishing any asset, verify:

- no guaranteed repair claim;
- no request for account login;
- no request for API keys, tokens, cookies, or private data;
- no payment/KYC/wallet/tax handling;
- no platform bypass claim;
- no fake customer proof.
