## 1. 基本信息

- 买家代号：demo-lead-001
- 平台：n8n / Make / Zapier 同类工作流
- 失败位置：Webhook 后的 JSON 字段映射到 CRM 步骤
- 诊断日期：2026-05-21
- 交付类型：入门诊断 / 固定范围报告

## 2. 买家目标

买家希望这个自动化流程完成：

- 表单产生新线索后，Webhook 接收数据，并把姓名、邮箱、公司、来源写入 CRM。

成功时应该输出：

- CRM 中新增一条包含 `email`、`company`、`source` 的线索记录。

## 3. 当前故障

买家描述的实际情况：

- Webhook 仍然可以触发。
- CRM 步骤失败。
- 部分线索没有进入 CRM。
- 重试后可能产生重复通知。

错误文本或异常表现：

```text
Mapped email field is empty
CRM request failed: missing required field email
retry_count: 3
duplicate_notification_risk: high
```

## 5. 初步判断

### 最可能原因

1. 上游表单 payload 结构变了，邮箱从 `email` 变成 `lead.email`。
2. 工作流仍然使用旧映射：`{{$json["email"]}}`。
3. CRM 步骤收到空邮箱后失败，重试设置导致重复通知风险升高。

### 风险等级

本次判断：中风险。

原因：

- 影响线索进入 CRM。
- 已出现重试 3 次。
- 如果不先关闭或限制重试，可能重复发送通知或重复调用付费步骤。

## 6. 失败节点地图

| 节点 | 期望表现 | 实际表现 | 可能问题 | 下一步 |
| --- | --- | --- | --- | --- |
| 触发器 / Webhook | 收到新线索 payload | 正常收到 | 触发器健康 | 保持不动 |
| HTTP / API | 不涉及或通过 | 未显示 API 鉴权错误 | 不是主要故障点 | 暂不优先排查 |
| JSON / 字段映射 | `email` 应映射到 CRM 邮箱 | 映射结果为空 | 字段路径仍用旧结构 | 改为 `lead.email` |
| AI / 模型步骤 | 不影响 email 字段 | 无 AI 错误 | 不是主要故障点 | 暂不处理 |
| 输出 / 通知 / CRM | CRM 接收完整线索 | 缺少 email 后失败 | 上游字段为空导致失败 | 先修复映射再测试 |

## 7. 建议修复顺序

1. 暂停自动重试或把重试次数降到 0-1，避免重复通知。
2. 用一条脱敏测试 payload 单独跑 JSON 映射节点。
3. 将邮箱映射从 `{{$json["email"]}}` 改为 `{{$json["lead"]["email"]}}`。
4. 将公司映射从 `{{$json["company"]}}` 改为 `{{$json["lead"]["company"]["name"]}}`。
5. 增加空邮箱保护：如果 `lead.email` 为空，则停止进入 CRM 步骤并记录错误。
6. 用测试模式跑一次完整链路，确认 CRM 接收 `email`、`company`、`source`。

针对本次问题的建议：

```text
email = {{$json["lead"]["email"]}}
company = {{$json["lead"]["company"]["name"]}}
source = {{$json["metadata"]["source"]}}
```
