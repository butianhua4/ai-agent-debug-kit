# 中文买家需求收集表：自动化故障诊断

用于微信、闲鱼、小红书、知乎、掘金、社群、Fiverr 买家消息里的初步需求收集。目标是把模糊咨询变成可报价、可交付、可拒绝的结构化信息。

不要收集或保存：密码、API Key、Token、Cookie、身份证、税务资料、付款信息、钱包私钥、未脱敏客户数据、后台登录权限。

## 一句话发给买家

可以，我先不碰账号，也不需要密码或 API Key。你按下面这个表填一下，我先判断能不能固定范围诊断，再给你 299 / 999 / 1999+ 哪个档位的建议。

## 买家填写区

```text
1. 你用的平台是什么？
   例如：n8n / Make / Zapier / Pipedream / 自建 Node.js / Python / 表格自动化 / 其他

2. 这个自动化原本要完成什么？
   例如：表单提交后同步到 CRM、AI 生成内容后发到飞书、Webhook 收到订单后发邮件

3. 现在失败在哪一步？
   例如：Webhook 收不到、HTTP 请求失败、JSON 字段映射错、邮件没发出、重复触发

4. 完整错误文本是什么？
   请复制错误内容；如果是截图，请先遮住账号、密钥、客户信息。

5. 最近改过什么？
   例如：改过字段名、换过 API、改过提示词、换过模型、改过节点、平台升级

6. 你期望输出是什么？
   例如：CRM 创建一条线索、表格新增一行、邮件正常发出、AI 返回固定 JSON

7. 实际输出是什么？
   例如：空字段、报错、重复发送、没有触发、成本异常、输出格式乱了

8. 影响范围有多大？
   A. 只是测试流程
   B. 影响个人工作
   C. 影响客户线索 / 内容生产 / CRM / 业务流程
   D. 正在造成损失，需要加急

9. 你能提供哪些脱敏材料？
   A. 错误文本
   B. 流程截图
   C. workflow 导出（已删除密钥和客户隐私）
   D. 输入样例
   E. 期望输出样例

10. 是否涉及敏感权限？
   支付 / KYC / 身份 / 税务 / 钱包 / 客户隐私 / 登录权限 / 私有仓库
```

## 操作员评分

| 字段 | 加分 |
| --- | ---: |
| 平台明确 | +2 |
| 失败步骤明确 | +2 |
| 有错误文本 | +2 |
| 期望输出明确 | +1 |
| 实际输出明确 | +1 |
| 接受脱敏边界 | +1 |
| 有业务紧急度 | +1 |

扣分：

| 风险 | 扣分 |
| --- | ---: |
| 一上来要求登录账号 | -3 |
| 涉及支付 / KYC / 钱包 / 身份 / 税务 | -3 |
| 要求绕过平台限制或抓取私密系统 | -3 |
| 拒绝脱敏 | -2 |
| 只说“帮我做自动化”但没有具体流程 | -2 |

## 报价映射

| 分数 | 动作 |
| ---: | --- |
| 0-3 | 拒绝或只问一个澄清问题 |
| 4-5 | 继续补充信息，不报价 |
| 6-7 | 报 299 RMB 入门诊断 |
| 8-9 | 报 999 RMB 标准救援报告 |
| 10 | 报 1999+ RMB 加急业务救援 |

## 自动回复模板

### 信息不足

我现在还不能准确报价，因为缺少失败步骤 / 错误文本 / 期望输出。你先补这三项，我再判断是否适合固定范围诊断。

### 299 入门诊断

这个问题适合先做 299 入门诊断。交付一页诊断报告：可能原因、失败步骤或字段、安全测试清单和下一步修复建议。默认不需要账号密码。

### 999 标准救援报告

这个涉及完整流程，建议做 999 标准救援报告。交付流程失败地图、根因分析、字段或 JSON 映射修复建议、重复发送/重试风险提示和 Before/After 测试清单。

### 1999+ 加急业务救援

如果这个流程正在影响线索、CRM、内容生产或业务运行，可以走 1999+ 加急救援。交付优先诊断、风险地图、修复顺序、备用路径、监控清单和团队交接报告。

### 安全拒绝

这个需求我暂时不能接，因为涉及账号敏感权限、支付/KYC/钱包/身份/税务/未脱敏客户数据。建议先走平台官方支持或内部有权限的人处理。我这边可以处理脱敏后的错误文本、失败步骤和流程逻辑诊断。

## 交付边界确认

接单前确认：

- 我只基于脱敏材料做诊断或修复建议。
- 不接触密码、API Key、Token、Cookie、支付、身份、税务、钱包、私密客户数据。
- 如果后续需要登录平台实施修复，必须重新确认权限、范围和安全边界。
- 交付物是报告、修复顺序、测试清单、可执行建议；不是保证恢复任何第三方平台。
